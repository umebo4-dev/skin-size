# GBF スキンサイズ比較ツール

スキンごとの画像(PNG)サイズ・CJS JSファイルサイズを収集・比較して、最も軽いスキン編成を特定するツール。

---

## 構成ファイル

| ファイル | 役割 |
|---|---|
| `collector.py` | mitmproxyアドオン。ゲームのURLを監視してサイズをDB保存 |
| `app.py` | Flask Webアプリ |
| `skinsize.db` | SQLiteデータベース |
| `images/` | 収集した画像（sd/quest/raid） |

---

## セットアップ

```
pip install mitmproxy flask
```

ブラウザのプロキシを mitmproxy（デフォルト `localhost:8080`）に向ける。

---

## データ収集

```
mitmdump -s collector.py
# dn.pyと同時使用する場合:
mitmdump -s dn.py -s collector.py
```

mitmproxy起動後にゲームをプレイするだけで自動収集される。

### 収集されるデータ

| タイプ | 収集タイミング | 内容 |
|---|---|---|
| `sd` | 編成・バトル中 | SDスプライト PNG |
| `quest` | 編成画面 | キャラ立ち絵 JPG |
| `raid` | バトル中 | バトル立ち絵 JPG |
| `cjs_npc` | バトル中 | `npc_*.js` アニメーションJS |

- `phit_*` はスキン非依存のため除外
- キャラ名は `raid/start.json` から自動取得
- 同一ファイルは1件のみ保存（静的ファイルのためサイズ不変）

### ファイル名の規則

```
{char_id}_{skin_num}[_{差分番号}][_s{属性番号}].jpg
例: 3040258000_02_101_s6.jpg
    └ char_id=3040258000, スキン02, 差分101, 属性6(水)
```

属性番号（_sN）は同一画像の属性違いのため1件にまとめて平均サイズを使用。

```
python app.py
```

`http://localhost:5000` をブラウザで開く。

## 画面説明

### キャラ一覧
- 名前が取得済みのキャラのみ表示（未検証は非表示）
- サムネイルはskin_num最小・属性最多のquest画像

### 詳細ページ

**上部3カード（最軽量まとめ）**
- SD / 編成 / バトルそれぞれの最軽量スキンを表示
- モードによって表示が変わる（後述）

**推奨モード（デフォルト）**
CJS最小のSDスキンを「推奨グループ」とし、同グループ内で編成・バトルも最軽量を選出。グループは赤枠でハイライト。

**個別モード**
SD・編成・バトルをそれぞれ独立に最軽量選出。

**グループ（外枠）**
同じ `char_id`（同一キャラの別アートワーク）をまとめた枠。背景色で識別。

### 算出方法

| 値 | 内容 |
|---|---|
| PNG | そのスキンの全画像ファイルサイズの合計 |
| CJS | `npc_{ID}_{スキン番号}.js` のサイズ。毎フレームの描画CPU負荷に直結 |

CJSが主指標（CPU負荷）、PNGが副指標（VRAM・転送コスト）。

### SD ソート
CJS順 / PNG順ボタンでグループ単位の並び替えが可能。

## 診断ツール（/check）

ナビバーの「適用漏れ確認」から開く。

画像が表示されない場合にファイル名を入力して原因を特定できる。

```
入力例: images/raid/3040032000_04.jpg
        3040032000_04.jpg   ← ファイル名だけでも可（自動でディレクトリを探索）
```

| 診断結果 | 対処 |
|---|---|
| DBに未登録・ディスクにあり | 「DBに登録する」ボタン |
| DBに未登録・ディスクになし | ファイルを選択して「アップロード＆登録」 |
| キャラ名なし | ゲームでそのキャラのraidをプレイしてキャラ名を取得 |

### よくある適用漏れの原因
quest と raid で同名ファイルが存在する場合、以前は quest が10件に達すると raid が登録されないバグがあった（修正済み）。該当キャラは診断ツールで個別に登録する。
